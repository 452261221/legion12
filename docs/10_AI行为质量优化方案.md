# 10 AI 行为质量优化方案

本文档承接 `09_AI开发方案.md` 的总体架构，聚焦脚本型 AI 的“行为质量”问题：不是先追求更深搜索，而是先把玩家一眼能看出的弱智动作压下去，形成稳定、可解释、可回归的优化闭环。

## 目标

1. 降低明显负收益动作的出现频率。
2. 让 AI 在保命、收头、换子、站位、资源投入上更接近正常玩家直觉。
3. 建立“文档 -> 特征/规则 -> 自博弈 -> battle log -> 回归用例”的长期优化流程。
4. 在不修改规则语义的前提下持续增强 AI。

## 当前问题画像

结合最近自博弈、battle log 与人工实测，当前 AI 的低质量行为主要分成六类：

### 1. 资源白烧

- 白烧士气位移：花士气移动，但没有抢到节奏、没有开主宰线、没有保命、也没有形成后续收益。
- 低价值启动：在没有压力的窗口启动神器或主动技，只换来很弱的即时价值。

### 2. 纯送死攻击

- 攻击力不够还硬撞，既没换掉对手，也没打到主宰，也没换来后续窗口。
- 明知会亏掉己方站场，仍然做单步负收益攻击。

### 3. 空发动/半截子发动

- 例如阿尔维达类“先弃置/先自损，再拖牌登场”的效果，在没有合法后续候选时仍然发动。
- 这类动作不是“亏一点换节奏”，而是纯亏。

### 4. 保命意识不足

- 濒死时仍然乱 `pass_priority`。
- 有挡刀、反击、主宰守卫可用时，未优先进入保命决策。

### 5. 省解意识不足

- 明明能用 blocker / supporter / 单卡主宰守卫解，结果去交更贵的手牌组合。
- 守住这一拍后直接进入低手、顶牌、无反打窗口。

### 6. 位置与阶段意识不稳定

- 没分清 opening / midgame / closing / desperation 的价值排序。
- 终结窗口不够凶，保命窗口又不够怂。

## 优化原则

### 1. 先治下限，再谈上限

优先消灭“明显不该发生”的动作，再继续抬高强度。

### 2. 先做窄规则，再做广搜索

对极少数确定是错的动作使用硬 veto；对大多数可讨论动作，仍然走特征 + 权重 + 轻量模拟。

### 3. 规则层不背 AI 债

AI 只能使用规则引擎已有合法动作与公开状态；不把策略判断塞回规则核心。

### 4. 所有优化必须可回归

每一类傻行为都要沉淀成 battle log 关键词、固定 seed、或单元测试，不接受“这次看起来好了”。

## 分层治理方案

推荐把 AI 行为治理拆成四层，从硬到底、从便宜到贵。

### L0：合法性底线

- 来源：`engine.get_legal_actions()` + `validate_command()`
- 目标：杜绝非法命令、过期候选、错误 payload
- 当前状态：已基本收敛

### L1：硬 veto 层

只拦截“高置信度负收益动作”，避免软权重被偶然局面冲穿。

第一批 veto 规则：

1. `suicidal_attack_no_followup`
   - 己方会损失站场
   - 敌方站场未减少
   - 敌方主宰未受伤
   - 己方也没有得到新的站场收益

2. `prefer_killable_defender_over_nonlethal_target`
   - 同一攻击者当前存在可击杀的合法单位目标
   - AI 却选择去打一个本回合打不死的高兵目标
   - 典型表现就是“明明能收小兵，却去白撞大兵”

3. `skip_stronger_defender_attack`
   - 当前攻击目标兵力严格高于攻击者
   - 这次进攻不会形成即时收益
   - 属于典型“撞高兵送死”

4. `move_legion_burns_morale_without_payoff`
   - 消耗活跃士气
   - 没有打伤主宰
   - 没有清场
   - 没有新增前排或站场收益

5. `move_legion_skips_available_attack`
   - 当前军团已在前排
   - 同一军团当前就存在合法攻击
   - 但 AI 仍选择额外位移而不是直接进攻
   - 典型表现就是“横跳烧士气，错过现成攻击窗口”

6. `pass_priority_skips_master_defense`
   - 主宰正处于被攻击状态
   - 当前存在合法 `ChooseDefense` / `hand_response` / `counter_tactic`
   - 这时 `pass_priority` 会直接放弃真实防守窗口

7. `prefer_non_guard_defense_over_multi_guard`
   - 当前候选为多卡 `master guard`
   - 但同时存在 blocker / supporter / 更便宜的 guard 方案
   - 典型目标是避免“有更省的解还乱交两张牌”

8. `effect_followup_missing`
   - 效果属于“从手牌继续登场”的 follow-up 型效果
   - 当前手牌里不存在合法目标，或战场无可登场空位
   - 典型例子：阿尔维达空发动

设计约束：

- veto 规则必须少而精，不允许泛滥。
- 若所有候选都被 veto，则自动回退到原排序，避免 AI 卡死。
- veto 结果必须回写到 `top_candidates` 与 debug summary，方便追日志。

### L2：特征与权重层

这是常规优化主战场，解决“该更倾向哪个合法动作”。

近期优先特征：

1. 防守窗口惩罚 `pass_priority`
   - `pass_priority_with_response_available`
   - `pass_priority_while_defending_master`
   - `pass_priority_skips_defense_action`
   - `pass_priority_skips_hand_response`
   - `pass_priority_skips_counter_tactic`
   - `pass_priority_in_survival_mode`

2. 资源成本意识
   - 士气损耗
   - 手牌损耗
   - 多卡主宰守卫税
   - 防守后是否进入低手/顶牌

3. 阶段意识
   - closing window：更敢收头、清最后前排、抢主宰线
   - survival mode：更敢保命、少乱 pass、少交纯亏动作

4. 站位意识
   - move 到前排是否形成压力
   - 从前排撤走是否暴露主宰线
   - 同列是否有 supporter

### L3：轻量前瞻层

由 `candidate_simulator.gd` 提供 top-N 单步模拟，重点不在“算多远”，而在把成本正式入模。

当前与下一步重点：

- 已有：
  - 主宰血量变化
  - 前后排数量变化
  - 手牌变化
  - 士气变化
  - 行动窗口保留/让渡

- 下一步继续补：
  - 防守后剩余总可防伤害
  - 多路直击压力
  - stack 上未兑现收益的估值折扣
  - 关键单位存活率

### L4：专项回归层

每一类典型傻行为都要有固定抓手：

1. 单元测试
   - 纯送死攻击 veto
   - 空 follow-up 效果 veto
   - 防守窗口 pass 惩罚特征

2. headless 自博弈
   - `tools/run_ai_selfplay.gd`
   - 重点看 battle log 的 `top_candidates / simulation_summary / veto_reason`

3. battle log 抽样
   - 复查最新对局里是否还出现 `pass_priority` 漏防
   - 复查 `MoveLegion` 是否仍频繁伴随无收益士气消耗
   - 复查 `ActivateEffect` 是否出现空 follow-up

## 本轮已落地项

### 1. 策略层硬 veto

落点：`ai/scripted/scripted_policy_profile.gd`

新增：

- 最终排序后、提交前增加硬 veto 过滤
- 对以下动作直接降级处理：
  - 纯送死攻击
  - 撞更高兵力军团的亏损攻击
  - 主宰受击时乱 `pass_priority`
  - 有便宜防守方案时优先交多卡主宰守卫
  - 白烧士气位移
  - follow-up 缺失的自损/献祭发动
- `top_candidates` 现会携带 `vetoed / veto_reason`

### 2. 防守窗口 pass 惩罚

落点：`ai/scripted/profile_feature_extractor.gd`

新增 priority context：

- 是否存在 response
- 是否在 defending master
- 是否有 choose_defense
- 是否有 hand response
- 是否有 counter tactic

新增特征：

- `pass_priority_with_response_available`
- `pass_priority_while_defending_master`
- `pass_priority_skips_defense_action`
- `pass_priority_skips_hand_response`
- `pass_priority_skips_counter_tactic`
- `pass_priority_in_survival_mode`

### 3. 两套预组权重同步

落点：`data/ai/profiles.json`

思路：

- 高天原：保持进攻性，但在保命窗口减少无脑 `pass_priority`
- 阿斯加德：更强烈惩罚防守窗口乱过优先权，进一步贴近中速防守风格

### 4. 最小版 `MoveLegion -> DeclareAttack` 前瞻

落点：`ai/scripted/candidate_simulator.gd`

新增：

- 当 `MoveLegion` 执行后仍保有自己的主阶段行动权时，额外检查该移动军团是否形成合法攻击机会
- 当前只做最小版 follow-up 机会评分，不展开完整两步搜索树

当前会奖励：

- 位移后直接获得 `attack master`
- 位移后获得更优单位交换
- 位移后能打掉最后前排
- 攻击打掉最后前排后形成后续主宰压力

设计目标：

- 先让 AI 认识“位移不是终点，位移后能不能出手才是关键”
- 为后续完整 `move -> attack` 双步评分和连段规划铺路

### 5. `MoveLegion -> DeclareAttack` 主排序双步骨架

落点：`ai/scripted/scripted_policy_profile.gd`

新增：

- 对 top-N `MoveLegion` 候选，在主排序阶段预览第一步后的局面
- 若仍保有自己的行动权，则继续枚举后续合法攻击
- 用“后续攻击静态分 + 后续攻击单步模拟分”形成 `followup_sequence_score`

当前输出：

- `followup_sequence_score`
- `followup_sequence_summary`
- `followup_sequence_payload`

设计意义：

- 让双步价值真正参与最终排序，而不是只停留在 simulator 的局部启发式里
- 为后续扩展到更多两步/三步序列保留同一条主链路

当前已接入主排序的两步序列：

- `MoveLegion -> DeclareAttack`
- `DeclareAttack(清最后前排) -> 后续主宰压力`
- `PlayCard/ActivateEffect -> 最佳主动 follow-up`

其中已显式强化的组合偏好包括：

- `ActivateEffect -> PlayCard`
- `ActivateEffect -> ActivateEffect`

## 还可以继续优化的完整方案

下面按优先级给出后续完整路线。

### P0：继续补底线行为

1. `ChooseDefense` 的最省资源解排序再细化
2. “可能当场致死”的主宰血线规则再前移
3. 对“多卡守卫但无后手”的动作做更强惩罚
4. 对“为了 1 点收益交掉关键反击牌”的动作做折扣

### P1：补关键局面理解

1. 斩杀线感知
   - 当前能否两路打死
   - 对手是否必须多卡守卫

2. 反杀线感知
   - 本回合贪攻击后，对手下回合是否能直接带走

3. 关键单位识别
   - 不是只看 power/cost，还要识别：
   - 解场核心
   - 返场核心
   - 续航核心
   - 反击核心

### P2：把“未兑现收益”显式建模

当前单步模拟对 stack、choice、延迟 follow-up 的估值还偏粗。

建议补：

- `expected_followup_candidates`
- `followup_requires_choice`
- `followup_pending_but_not_secured`
- `stack_value_realization_risk`

这样能更好地区分：

- 真正会兑现的连段
- 看起来有收益，其实下一步大概率空掉的动作

### P3：更强的对手响应建模

当前只做了有限的主宰守卫/反制风险估计，后续可增强：

1. 明牌 set counter 风险
2. 手牌规模对应的主宰守卫上限
3. 对手前后排可支援关系
4. 对手下回合爆发概率

### P4：建立行为专项 case 库

建议新增一个 AI case 清单，按行为类型维护：

- `cases/ai/suicidal_attack`
- `cases/ai/morale_burn_move`
- `cases/ai/alvilda_empty_followup`
- `cases/ai/critical_defense_window`
- `cases/ai/master_guard_tax`

每个 case 至少保存：

- 初始 deck / seed
- 关键局面构造方式
- 期望禁止动作
- 期望优先动作

### P5：中长期增强

在底线行为稳定后，再继续抬上限：

1. top-N 双步搜索
2. profile 自适应微调
3. 基于 battle log 的离线权重校准
4. LLM 仅接管复杂主阶段的高层规划

## 验收指标

### 质量指标

- battle log 中 `veto_reason` 命中频率稳定下降
- 漏防主宰的 `pass_priority` 显著减少
- 空发动 / 纯送死攻击在固定回归 case 中归零

### 稳定性指标

- 自博弈 smoke 持续 `EXIT_CODE=0`
- 不新增非法命令
- 不新增脚本加载错误

### 可解释性指标

- 每个高风险决策都能在 `top_candidates` 中看见
  - 静态分
  - 模拟分
  - veto 原因
  - 关键特征摘要

## 推荐执行顺序

1. 先把 P0 做满，继续压低最恶心动作。
2. 再做 P1/P2，让 AI 真正开始理解“我这步会不会把自己玩死”。
3. 最后再做 P3/P5，抬高博弈上限。
