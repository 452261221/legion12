# 06 开发路线图

路线图以“先稳定底层，再扩卡牌，再做产品功能”为原则。早期不要追求完整主界面，也不要急着做联机或 AI。

## 阶段 0：项目骨架与文档

目标：

- 建立 Godot 项目。
- 建立 `rules/`、`client/`、`data/`、`tests/` 目录。
- 建立基础文档。
- 确认 Godot 版本。

交付：

- `project.godot`
- 文档集。
- 空 BattleScene。
- headless 测试脚本可运行。

验收：

- Godot 可打开项目。
- headless 测试命令可运行。

## 阶段 1：规则核心最小闭环

目标：

- 能初始化一局。
- 能抽牌。
- 能推进回合。
- 能出普通军团。
- 能普通进攻。
- 能结算阵亡。

交付：

- GameState。
- PlayerState。
- Zone。
- CardDefinition。
- CardInstance。
- Command。
- Event。
- PhaseMachine。
- 基础 actions。

验收：

- 两个测试卡组能跑 5 回合。
- 单元测试通过。
- 状态 validator 无错误。

## 阶段 2：Godot 对战调试客户端

目标：

- 将规则核心可视化。
- 支持本地双方操作。
- 支持调试面板。

交付：

- 牌桌布局。
- 手牌。
- 战场。
- 主宰与血量。
- 牌库、墓地、士气、圣物、天灾区。
- 出牌与进攻输入。
- 基础动画。
- 调试面板。

验收：

- 可以用鼠标完成基础对战。
- 可以强制抽牌、设置血量、移动卡。
- 命令和事件日志可查看。

## 阶段 3：堆叠、响应、持续效果

目标：

- 建立真正可扩展的效果系统。

交付：

- Stack。
- Priority。
- TriggerQueue。
- Reaction window。
- Modifier system。
- Replacement window。
- Cost/effect 分离。

验收：

- 主动效果可被响应。
- 触发式效果可被响应。
- 持续效果不可响应。
- cost 支付后效果被无效不回滚。
- Q&A 核心测试通过。

## 阶段 4：天灾系统

目标：

- 完成天灾值与天灾牌。

交付：

- 天灾值变化。
- 翻开天灾。
- 持续天灾。
- 触发天灾。
- 最终天灾。
- 天灾调试工具。

验收：

- 回合结束天灾值 +1。
- 天灾值高于 8 触发。
- 天灾效果能影响场面。
- 天灾无法被隐匿等规避。

## 阶段 5：基础关键词与通用卡牌

目标：

- 实现常见关键词。
- 导入基础卡牌。

交付：

- 冲锋。
- 远程。
- 挑衅。
- 免死。
- 必中。
- 支援。
- 无法进攻。
- 进攻无损。
- 简单抽牌、弃牌、检索、击杀。

验收：

- 第一批测试卡牌全部可用。
- 关键词测试通过。

## 阶段 6：阵营机制

目标：

- 支持每个阵营的核心玩法。

优先顺序：

1. 通用。
2. 阿斯加德。
3. 高天原。
4. 太阳城。
5. 天庭。
6. 奥林匹斯神力。
7. 彼界符文与试炼。
8. 晋升与叠放。

验收：

- 每个阵营有一套可跑的测试牌组。
- 至少能完成 20 回合人工对局。

## 阶段 7：卡牌批量实现

目标：

- 逐张实现卡牌。

流程：

1. 数据导入。
2. 效果拆分。
3. handler。
4. 测试。
5. UI 手测。

验收：

- 卡牌状态从 `raw_imported` 推进到 `tested`。
- 每个复杂效果至少一个测试。

## 阶段 8：牌库构筑与主界面

目标：

- 做产品化入口。

交付：

- 主界面。
- 本地牌库构筑。
- 保存/读取牌组。
- 对局历史。
- 回放浏览。
- 设置。

验收：

- 可从主界面选择牌组进入对战。
- 可查看历史和回放。

## 阶段 9：AI

目标：

- 做可调试 AI，对玩家练习和自动测试有帮助。

初版 AI：

- 随机合法行动。
- 简单启发式。
- 可自动跑局。

进阶 AI：

- 估值函数。
- 蒙特卡洛。
- 策略脚本。

验收：

- AI 可完整打完一局。
- 自动跑 100 局无崩溃。

## 阶段 10：联机

目标：

- 双端共享规则核心。
- 服务器只接受命令，验证并广播事件。

前置条件：

- 回放稳定。
- 命令确定性稳定。
- 随机 seed 稳定。
- 隐藏信息处理清楚。

验收：

- 本地双客户端联机。
- 断线重连可从命令日志恢复。
- 服务器能拒绝非法命令。

## 风险优先级

最高风险：

- 响应/堆叠。
- 触发队列。
- 替代死亡。
- cost 与效果分离。
- 置入与登场。
- 天灾。

中风险：

- 试炼。
- 晋升。
- 主宰变军团。
- 叠放。
- 支援。

低风险：

- 普通抽牌。
- 普通出牌。
- 普通墓地。
- 基础 UI。

## 第一月建议目标

如果按多 agent 开发：

第 1 周：

- Godot 项目骨架。
- 规则核心数据结构。
- headless 测试入口跑通。
- 牌桌静态 UI。

第 2 周：

- 阶段机。
- 抽牌、士气、出军团。
- 基础 ViewModel。
- 调试面板雏形。

第 3 周：

- 进攻。
- 阵亡。
- 墓地。
- 命令日志。
- 回放雏形。

第 4 周：

- 堆叠。
- 触发。
- 响应。
- 第一批 Q&A 测试。
- 第一批简单卡牌。
